# ZONBER 이벤트 · 홍보 — v1.1 (2026-09-25)

> 목표는 하나다. **새 사람이 들어오고, 들어온 김에 한 판 더 하게.**
> 큰 시즌 이벤트·배틀패스는 만들지 않는다. 운영자가 5분 안에 열고 닫을 수 있는 가벼운 것만 둔다.
> 보상은 **코인과 외형 아이템뿐**이다 — 랭킹은 순수 실력 경쟁으로 남긴다([SHOP.md](SHOP.md)).

|---|---|---|---|---|---|

| `global_launch_2026` | **글로벌 출시 기념** | `bonus` · 1회 | 코인 500 | 2026-09-25 ~ 10-31 | 출시 첫 달 유입 환영 |
| `weekly_gift` | **주간 선물** | `bonus` · 168시간마다 | 코인 100 | 늘 | 매주 돌아올 이유(복귀) |
| `halloween_2026` | **할로윈 파티** | `bonus` · 1회 | 코인 300 + 불꽃 잔상 | 2026-10-24 ~ 11-02 | 세계 공통 시즌 |
| `holiday_2026` | **연말 선물** | `bonus` · 1회 | 코인 500 + 눈송이 잔상 | 2026-12-20 ~ 2027-01-04 | 크리스마스·새해 |
| `sns_codes` | **공식 SNS 코드** | `code` · 안내 카드 | 코드마다 다름(§2) | 늘 | SNS 팔로우 → 코드 입력 유도 |

기간이 있는 이벤트는 그 기간에만 보인다(기간은 UTC — 어느 나라에서나 같은 순간에 열리고 닫힌다).
기본 이벤트의 보상·기간·문구는 백오피스에서 같은 id 로 저장하면 **서버 값이 이긴다**(앱 업데이트 없이 수정).

### 공유하기가 보내는 문구

```
나 ZONBER에서 이만큼 버텼다!
ZONE 1 갤럭시 128.456s · ZONE 2 피구 96.212s
내 코드 K7PQ — 이벤트 화면에서 입력하면 코인 200!
https://play.google.com/store/apps/details?id=com.zonber.game
```

`공유하기`를 누르면 OS 공유 창(`share_plus`)이 바로 떠서 카톡·인스타·X·디스코드 등 SNS로 보낸다.
공유 창을 닫기만 하면 보상은 없고, 이미 받은 날에도 공유 자체는 된다. 공유 창을 못 띄우는 기기는 문구를 클립보드에 복사해 준다.
게스트는 친구 코드가 없어서 코드 줄 없이 기록·링크만 나간다.

### 친구 코드 (`FriendCodes` · `FriendService`)

회원마다 **고유 코드 하나** — 영문 대문자·숫자 **4~5자**(헷갈리는 글자 0 O 1 I L 없음). 처음 이벤트 화면을 열 때 만든다
(4자로 3번 시도 → 겹치면 5자). 공유하기 줄 제목 옆에 `K7PQ ⧉` 칩으로 보이고 누르면 복사된다.

| 누가 | 보상 | 언제 |
|---|---|---|
| 코드를 **넣은** 친구 | 코인 200 (`newcomerCoins`) | 이벤트 화면 코드 입력칸에 넣자마자. **계정당 친구 코드 한 번** |
| 코드 **주인** | 친구 1명당 코인 200 (`inviterCoins`), **최대 10명**(`maxRewarded`) | 다음에 이벤트 화면을 열 때 "친구 n명이 내 코드를 입력했어요!" |

- 입력칸은 이벤트 코드와 **같은 칸** — 이벤트 코드(`promo_codes`)를 먼저 찾고, 없고 4~5자면 친구 코드로 본다.
  이름이 겹치지 않게 친구 코드를 만들 때 이벤트 코드를, 백오피스가 이벤트 코드를 만들 때 친구 코드를 확인한다.
- 자기 코드 → "내 코드는 입력할 수 없어요" · 두 번째 친구 코드 → "친구 코드는 한 번만 입력할 수 있어요"
- 저장: `friend_codes/{코드}` {uid} · `users/{uid}.friendCode` · `friend_invites/{넣은 사람 uid}` {code, inviter, rewarded}
- 규칙(`firestore.rules`): 코드는 한 사람 하나(유저 문서에 처음 적을 때만), 입력 기록은 문서 id 가 넣은 사람 uid 라
  계정당 한 번이고 넣은 사람은 지우지 못한다(지우고 다시 넣기 방지). 코드 주인은 `rewarded` 를 false → true 로만 바꾼다.
- 탈퇴하면 내 친구 코드를 지운다(더는 아무도 못 넣는다). 보상 수치는 `promotions.dart` 의 `FriendCodes` 상수.

### 이벤트 화면 규칙

한 줄 = **제목 + 설명 한 줄**(왼쪽) · **버튼**(오른쪽). 설명은 짧게 쓴다 — 길면 글자가 줄어들며 한 줄에 맞춰진다
(예: `코인 300 + 구름 스킨`, `기록 공유하면 매일 코인 50`). 백오피스에서 설명을 넣을 때도 같은 길이로.
코드 입력칸은 화면 맨 아래에 붙어 있어 키보드가 올라오면 키보드 바로 위로 올라간다.

## 2. 이벤트 코드 (운영자)

코드는 이벤트와 따로 논다 — **코드 하나 = 보상 하나.** `promo_codes/{코드}` 문서에 보상·캠페인·한도·기간이 있다.

### 만들기 — 백오피스 → **이벤트 코드** → `코드 만들기`

| 칸 | 뜻 |
|---|---|
| 코드 | **직접 입력**(모두가 같은 코드, 예: `ZONBER2026`) 또는 **자동 생성**(접두어 + 무작위 N자, 최대 200개 한 번에 — 1인 1코드 배포·경품용). 영문 대문자·숫자 4~20자, 헷갈리는 글자(0 O 1 I L)는 자동 생성에 안 쓴다 |
| 캠페인 | 어디에 뿌린 코드인지(`insta_launch`, `youtube_abc`). **채널별 유입을 가르는 이름** |
| 메모 | 운영 메모(앱에 안 보임) |
| 보상 | 코인 + 아이템(게임에 있는 목록에서 고른다 — 오타 불가) |
| 전체 사용 한도 | 선착순 N명(0 = 무제한). **한 사람은 늘 한 번** |
| 기간 · 켜기 | 끝나면 자동으로 막힌다. 바로 멈추려면 **끄기** |

저장 전에 "유저가 이 코드를 넣으면 → 코인 500 · 1인 1회 · 선착순 100명" 미리보기가 보이고, 숫자 확인을 거친다.

### 검증 — `코드 확인`

유저가 넣을 글자 그대로(소문자·공백·하이픈 포함) 넣으면 앱과 같은 기준으로 정리·판정해서
**상태(사용 가능·꺼짐·시작 전·기간 끝·한도 소진) · 보상 · 캠페인 · 사용 수 · 앱에 뜨는 문구**를 보여 준다.
목록의 **사람 아이콘**은 그 코드를 쓴 유저(최근 순, 누르면 유저 상세)다.

### 앱에서 코드를 넣으면

| 결과 | 앱 문구 |
|---|---|
| 성공 | `코인 500 · 구름 받았어요!` (그 코드의 보상 그대로) |
| 없는 코드·형식 틀림 | 없는 코드예요 |
| 이미 쓴 계정 | 이미 사용한 코드예요 |
| 꺼짐 / 시작 전 / 기간 끝 / 한도 소진 | 사용이 중지된 / 아직 쓸 수 없는 / 기간이 끝난 / 선착순이 모두 끝난 코드예요 |
| 게스트 | 로그인 안내 |

### 서버 검증 (firestore.rules)

- **코드가 새지 않는다** — 회원은 코드를 알 때만 그 문서 한 건을 `get` 할 수 있다. 목록(`list`)은 관리자만.
  (예전엔 코드가 `promos` 문서 안에 있어 누구나 목록으로 읽을 수 있었다)
- **1인 1회 · 한도 · 기간** — 사용은 트랜잭션 한 번: `users/{uid}/codes/{코드}` 생성 + `promo_codes/{코드}.uses` +1.
  규칙이 둘을 묶어 검사한다 — 사용 기록이 **새로** 생길 때만 +1, +1 될 때만 기록 생성, 켜짐·기간 안·`uses < maxUses` 일 때만.
  이미 기록이 있으면 create 가 아니라 update 라서 막힌다. 보상 값 수정·+2 도 막힌다.
- 시험: `node scripts/test_rules.mjs` (코드 규칙 20건 포함)
- 보상 지급(코인·아이템)은 앱이 한다 — 서버 함수가 없으므로 코인 값 자체는 `validUser` 범위 검사까지다.

> 배포: `deploy_admin.bat`(호스팅 + 규칙 + 색인). 코드별 사용자 조회는 collection group `codes.code` 색인이 필요하다(firestore.indexes.json).

## 4. 구조 (개발자)

```
lib/promotions.dart              Promotion · Promotions.builtIn · PromoCode/PromoCodes(정리·형식·생성) · PromoService(받기·redeem)
                                 · FriendCodes/FriendService(내 친구 코드·친구 코드 넣기·주인 보상)
lib/pages/promo_page.dart        PromoBanner(홈 한 줄) · PromoPage(이벤트 페이지 'Promo' — 받기·코드 입력·공유하기·내 코드 칩)
lib/backoffice/promo_page.dart   이벤트(추가·수정·켜고 끄기·받은 수)
lib/backoffice/promo_codes_page.dart  이벤트 코드(만들기·수정·켜고 끄기·코드 확인·사용한 사람)
firestore.rules                  promos · promo_codes · users/{uid}/promos · users/{uid}/codes · friend_codes · friend_invites
```

- **새 이벤트를 여는 두 가지 길**
  1. 운영자 — 백오피스에서 `promos/{id}` 추가 (앱 업데이트 없음, 즉시 반영)
  2. 개발자 — `Promotions.builtIn` 에 한 줄 (앱에 늘 들어 있는 기본 이벤트, 4개 언어 모두 — 테스트가 검사)
  같은 id 면 **서버 값이 이긴다.** 단, 받은 수 카운터(`claims`)만 든 문서는 정의가 아니다(`Promotions.fromServer`).
- 화면은 목록을 그릴 뿐이라 **이벤트가 늘어도 UI 는 손대지 않는다.** 종류를 새로 만들 때만 코드가 필요하다.
- 이벤트 중복 수령 차단: 기기(SharedPreferences) + 계정(`users/{uid}/promos/{id}`). 로그인하면 계정 기록을 먼저 읽어
  다시 깔아도 두 번 받지 못한다. 게스트는 아예 받지 못한다(아무것도 저장하지 않는 원칙 그대로).
- 받은 사람 수는 `promos/{id}.claims` 를 +1 해서 센다(규칙이 +1 만 허용).
- 문구는 없는 언어면 영어, 영어도 없으면 한국어로 보인다(`Promotion.textOf`).

## 5. 재면 좋은 것

| 숫자 | 어디서 |
|---|---|
| 코드별 사용 수 = 채널별 유입 | 백오피스 이벤트 코드 목록의 **사용 / 한도** (캠페인으로 검색) |
| 신규 가입 추이 | 대시보드 신규 가입 차트 |
| 공유하기 수령 수 = 공유 횟수 | 이벤트 목록(`share_daily`) |
| 친구 코드로 들어온 사람 | `friend_invites` 문서 수(inviter 별) |
| 들어와서 한 판 했는지 | 플레이 기록(회원 판) |
