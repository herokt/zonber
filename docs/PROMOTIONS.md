# ZONBER 이벤트 · 홍보 — v1.0 (2026-09-25)

> 목표는 하나다. **새 사람이 들어오고, 들어온 김에 한 판 더 하게.**
> 큰 시즌 이벤트·배틀패스는 만들지 않는다. 운영자가 5분 안에 열고 닫을 수 있는 가벼운 것만 둔다.
> 보상은 **코인과 외형 아이템뿐**이다 — 랭킹은 순수 실력 경쟁으로 남긴다([SHOP.md](SHOP.md)).

## 1. 지금 도는 이벤트 세 가지

| 이벤트 | 종류 | 보상 | 노리는 것 |
|---|---|---|---|
| **환영 선물** | `welcome` · 계정당 1회 | 코인 300 + 구름 스킨 | 들어오자마자 꾸밀 게 생긴다 → 첫 이탈 줄이기 |
| **친구에게 자랑하기** | `share` · 하루 1회 | 코인 50 | **유입 경로 자체** — 내 기록 문구 + 스토어 링크를 복사해 준다 |
| **홍보 코드** | `code` · 코드당 1회 | 운영자가 정함(예: 코인 500) | 커뮤니티·SNS에 뿌린 코드로 유입을 센다 |

앞의 둘은 앱에 기본으로 들어 있어서 서버가 없어도 돈다(`Promotions.builtIn`).
코드 이벤트는 **백오피스에서 만든다** — 캠페인마다 코드를 새로 파면 된다.

카톡·디스코드·커뮤니티 어디든 붙는다.

## 2. 홍보 코드 굴리는 법 (운영자)

1. 백오피스 → **이벤트** → `새 이벤트`
2. 종류 `코드 입력`, id 는 캠페인 이름(`reddit_1002`, `insta_launch` …), 코드는 짧고 대문자로(`ZONBER`)
3. 보상(코인·아이템 id)과 기간을 넣고 저장 → **앱에 바로 반영**(앱 업데이트 불필요)
4. 코드를 글·영상·댓글에 적어 배포
5. 목록의 **받은 수**가 그 채널로 들어온 사람 수다 — 채널마다 코드를 다르게 파면 어디서 왔는지 갈린다

> 코드는 앱에서 검사한다(서버 함수 없음). 코인·외형만 주므로 새어 나가도 랭킹에는 영향이 없다.
> 값이 큰 보상은 기간을 짧게 잡고, 캠페인이 끝나면 **끄기**로 내린다.

## 3. 다음에 열어 볼 만한 것들 (같은 구조로 코드 수정 없이)

| 아이디어 | 만드는 법 |
|---|---|
| 주말 복귀 선물 | 종류 `기간 보상`, 금~일 기간, 코인 200 |
| 신캐릭터 출시 기념 | 종류 `기간 보상`, 아이템 `char_frost_cyan` |
| 유튜버 협업 코드 | 종류 `코드 입력`, 코드 = 채널 이름 |
| 업데이트 사과 보상 | 종류 `기간 보상`, 기간 3일 |

## 4. 구조 (개발자)

```
lib/promotions.dart        Promotion(모델) · Promotions.builtIn(앱 기본) · PromoService(불러오기·받기·기록)
lib/pages/promo_sheet.dart PromoBanner(홈 한 줄) · 이벤트 창(받기·코드 입력·자랑하기)
lib/backoffice/promo_page.dart  운영 화면(추가·수정·켜고 끄기·받은 수)
firestore.rules            promos(공개 읽기·관리자 쓰기) · users/{uid}/promos(본인 기록)
```

- **새 이벤트를 여는 두 가지 길**
  1. 운영자 — 백오피스에서 `promos/{id}` 추가 (앱 업데이트 없음, 즉시 반영)
  2. 개발자 — `Promotions.builtIn` 에 한 줄 (앱에 늘 들어 있는 기본 이벤트)
  같은 id 면 **서버 값이 이긴다** — 기본 이벤트의 보상·기간도 백오피스에서 덮어쓸 수 있다.
- 화면은 목록을 그릴 뿐이라 **이벤트가 늘어도 UI 는 손대지 않는다.** 종류를 새로 만들 때만 코드가 필요하다.
- 중복 수령 차단: 기기(SharedPreferences) + 계정(`users/{uid}/promos/{id}`). 로그인하면 계정 기록을 먼저 읽어
  다시 깔아도 두 번 받지 못한다. 게스트는 아예 받지 못한다(아무것도 저장하지 않는 원칙 그대로).
- 받은 사람 수는 `promos/{id}.claims` 를 +1 해서 센다(규칙이 +1 만 허용). 색인이 필요 없다.

## 5. 재면 좋은 것

| 숫자 | 어디서 |
|---|---|
| 코드별 수령 수 = 채널별 유입 | 백오피스 이벤트 목록의 **받은 수** |
| 신규 가입 추이 | 대시보드 신규 가입 차트 |
| 자랑하기 수령 수 = 공유 횟수 | 이벤트 목록(`share_daily`) |
| 들어와서 한 판 했는지 | 플레이 기록(회원 판) |

⚠️ 보상 수치를 바꾸면 이 문서와 백오피스 값을 같이 맞춘다. 코인 경제 수치는 [SHOP.md](SHOP.md) 가 정본.
