# ZONBER — 데이터 보안(Play) · 앱 개인정보 보호(App Store) 답안

> 2026-10-12 작성 · 앱 2.0.6 기준. **SDK 를 넣거나 빼면(인앱 결제 켜기 포함) 다시 맞춘다.**
> 근거: 앱이 쓰는 SDK — AdMob(`google_mobile_ads`) · Firebase Analytics · Auth(Google/Apple 로그인) · Firestore · Functions · Messaging(FCM)
> 과 앱이 직접 저장하는 것 — `users/{uid}`(닉네임·국가·아바타·기록) · `users/{uid}/private/account`(이메일) · `users/{uid}/runs`(판 기록) · `users/{uid}/devices`(친구 알림 토큰).
> SDK 공식 안내: [AdMob(Android)](https://developers.google.com/admob/android/privacy/play-data-disclosure) · [Firebase(Android)](https://firebase.google.com/docs/android/play-data-disclosure) · [Google Analytics](https://support.google.com/analytics/answer/11582702) · [AdMob(iOS)](https://developers.google.com/admob/ios/privacy/data-disclosure)

## 지금 문제

| 스토어 | 지금 공개된 내용 | 실제 |
|---|---|---|
| Google Play | **"수집된 데이터 없음 · 공유 없음"** | AdMob 이 IP(대략적 위치)·광고 ID·앱 상호작용·진단을 **수집하고 공유**한다. 로그인하면 이메일·닉네임·기록을 저장한다 → **정책 위반**(업데이트 거부·앱 내림 사유) |
| App Store | 추적·연결: 식별자 · 사용 데이터 · 진단 | **대략적인 위치**(AdMob·Analytics 가 IP 로 추정) · **이메일**(로그인 계정) · 게임 기록이 빠졌다 |

게스트(로그인 안 함)는 앱이 아무것도 저장하지 않지만 **SDK(광고·분석)는 게스트에게서도 자동으로 수집한다** — 그래서 "수집 없음"은 틀리다.

### 2. 데이터 유형 (체크할 것만)

필수 = 사용자가 끌 수 없음(SDK 가 자동으로 모음) · 선택 = 로그인한 사람만. **일시적으로만 처리? → 전부 아니요.**

| 분류 › 유형 | 수집 | 공유 | 필수/선택 | 목적 | 무엇 |
|---|:-:|:-:|:-:|---|---|
| 위치 › **대략적인 위치** | ✅ | ✅ | 필수 | 광고 또는 마케팅 · 분석 · 사기 방지, 보안, 규정 준수 | AdMob·Analytics 가 IP 로 추정 |
| 개인 정보 › **이름** | ✅ | — | 선택 | 앱 기능 · 계정 관리 | 닉네임(랭킹에 보임) |
| 개인 정보 › **이메일 주소** | ✅ | — | 선택 | 계정 관리 | Google 로그인 계정 이메일(본인만 보임) |
| 개인 정보 › **사용자 ID** | ✅ | — | 선택 | 앱 기능 · 계정 관리 | Firebase 계정 ID · 친구 코드 |
| 개인 정보 › **기타 정보** | ✅ | — | 선택 | 앱 기능 | 직접 고른 국가(국가 랭킹) |
| 앱 활동 › **앱 상호작용** | ✅ | ✅ | 필수 | 분석 · 광고 또는 마케팅 · 사기 방지, 보안, 규정 준수 | Analytics 이벤트(화면·판 시작/끝) · AdMob(앱 실행·탭·광고 시청) |
| 앱 활동 › **기타 작업** | ✅ | — | 선택 | 앱 기능 · 분석 | 게임 기록 — 판 기록·랭킹 기록·뱃지·코인 |
| 앱 정보 및 성능 › **진단** | ✅ | ✅ | 필수 | 분석 · 광고 또는 마케팅 | AdMob 성능 정보(실행 시간·멈춤·전력) |

> "공유"는 **AdMob(광고)** 때문에 체크한다. Firebase 는 우리를 대신해 처리하는 서비스 제공자라 공유가 아니다.

## App Store — 앱 개인정보 보호

App Store Connect › 앱 › **앱이 수집하는 개인정보** › 항목마다 편집. 창의 마지막 버튼이 **게시**라 저장하는 즉시 공개된다(새 빌드·심사 필요 없음, 임시 저장 없음).

> **2.1.2(217)부터 추적 안 함**(2026-10-17) — 광고가 전부 아동 대상(`tagForChildDirectedTreatment: yes`, 맞춤 광고 없음)이 되면서
> 앱이 iOS 추적 허용(ATT) 창을 더 띄우지 않는다. 그래서 **모든 항목의 "추적에 사용"을 아니요**로 바꾼다.
> 라벨에 추적이 남아 있는데 ATT 창이 없으면 심사에서 5.1.2 로 거절된다 — **2.1.2 를 심사에 내기 전에** 바꿔서 게시한다.
> 마지막 남은 추적 항목은 바이너리에 `NSUserTrackingUsageDescription` 이 있으면 App Store Connect 가 게시를 막는다
> ("…추적하기 위한 권한을 요청할 것임을 나타내는 NSUserTrackingUsageDescription이 포함되어 있습니다") — 그래서 217 에서 키를 뺐다(216 은 키가 남아 있어 심사에 쓰지 않는다).
> 같이 확인: AdMob 콘솔 › 개인정보 보호 및 메시지 › **IDFA 안내 메시지(iOS)가 게시돼 있지 않은지** — 있으면 그 메시지가 키 없이 ATT 창을 띄우려 한다.
>   2026-10-17 확인: ZONBER 용 IDFA 메시지 없음(게시된 1개는 다른 앱 HaruGrim 것).
>
> 2026-10-17 진행: 대략적인 위치 · 기기 ID · 제품 상호 작용 · 광고 데이터 · 충돌 데이터 · 실적 데이터 → 추적 아니요 게시. **기타 진단 데이터**는 217 처리 뒤 게시.

있어야 하는 항목(추적은 전부 **아니요**):

| 분류 › 유형 | 용도 | 사용자와 연결 | 추적에 사용 | 무엇 |
|---|---|:-:|:-:|---|
| 위치 › **대략적인 위치** | 타사 광고 · 분석 | 예 | 아니요 | AdMob·Analytics 가 IP 로 추정 |
| 연락처 정보 › **이메일 주소** | 앱 기능 | 예 | 아니요 | Google·Apple 로그인 계정 이메일 |
| 사용자 콘텐츠 › **게임 플레이 콘텐츠** | 앱 기능 | 예 | 아니요 | 판 기록·랭킹 기록 |

이미 있는 항목 안에서 이것들이 체크돼 있는지도 본다:

- 식별자 › **사용자 ID**(닉네임·계정 ID — 앱 기능, 연결, 추적 아니요) · **기기 ID**(IDFV·앱 인스턴스 ID·FCM 토큰 — 타사 광고·분석·앱 기능, 추적 아니요. IDFA 는 ATT 를 묻지 않으니 받지 않는다)
- 사용 데이터 › **제품 상호작용** · **광고 데이터**(AdMob)
- 진단 › **충돌 데이터** · **성능 데이터** · **기타 진단 데이터**(AdMob)
